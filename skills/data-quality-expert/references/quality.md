# 交付前检查

1. 输入范围是用户选定的CSV及相关规则；确认编码、字段映射和记录数，未读到正文不能称已检查。
2. 三个入口与实际任务对应；数值异常仅检查明确选择的指标，编号/手机号不默认扫描。
3. 保存真实执行命令、stdout、stderr和退出码。0仅表示所检查范围无发现；2是报告含待复核项；3是处理失败。未执行的步骤不能补成通过。
4. 打开输出文件并核对记录数量、至少一个问题定位及其原值；不存在文件时不能生成下载链接。默认交付可读的中文业务报告，标题、表头、状态、原因和建议不使用未解释的英文；必要时另存完整 JSON，不能把英文键 JSON 倾倒当成客户报告。
5. 缺失阈值在text/JSON口径一致；IQR显式阈值、Z-score和Modified Z-score的阈值没有被替换。小样本、零方差和零MAD均披露。
6. 所有NaN/inf、超范围数值、非数值指标、重复表头或坏行有明确报告或拒绝；不能吞掉后称干净。
7. 质量分数附覆盖率、维度检查次数和UNKNOWN项。没有业务阈值就不写“可上线”“可训练”“已符合监管”。
8. 原始文件hash在运行前后相等；脚本只新建结果文件，不覆盖输入或已存在输出。若输入在运行期间变化，应重跑稳定副本。
9. 给用户完整结果、主要待复核问题和可执行下一步；用户只修改一个字段或规则时保留未涉及成果，使用新版本报告，不重新编造全部口径。

本地验收与WorkBuddy真实调用、用户取得文件及付费权益是不同状态。未在目标环境运行时明确写待验证，不据本地输出声称已经上架。
