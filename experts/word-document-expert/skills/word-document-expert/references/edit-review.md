# 读取、局部编辑与审阅

## 读取与保护

先记录原文件 SHA256、内部部件列表和本次修改范围。读取正文可使用 `pandoc -t markdown 输入.docx`；读取修订时明确接受视图、拒绝视图还是全部修订，不把其中一个视图当作源文档全部信息。页眉页脚、批注、图片、关系与样式另读 OOXML 部件。图片里的文字不能据文件名推测。

旧 DOC 先用 `python3 scripts/run.py convert --headless --convert-to docx --outdir 新目录 输入.doc` 转换，保留原件，检查转换结果再编辑。

使用 `scripts/office_helpers.py` 中的 `safe_extract` 解包到新工作目录。它拒绝路径穿越和符号链接条目；不要直接执行压缩包中的文件。重新打包用同文件的 `rezip`，目标选择未存在的新路径。输入和输出不能相同。

## 定点修改

文本可能分在多个 `<w:r>` 中。先检查范围，只在确有需要时在工作副本运行：

```bash
python3 scripts/run.py merge-runs 工作目录
```

也可对副本 DOCX 使用 `-o 新文件.docx`。合并只应连接同格式的相邻 run；合并前后检查原文、修订、批注边界与显示。找到目标后定点修改 `word/document.xml` 或用户指定的部件，不格式化/美化整份 XML；替换图片保留关系 ID 或同步更新关系和内容类型。不要整体重建已有文件。

至少验证未目标段落文字、既有列表结构和所有未指定部件。用：

```bash
python3 scripts/run.py preserve 原件.docx 新稿.docx --allow-part word/document.xml
```

新增批注或图片时把实际需要变化的部件逐项列入允许清单；不能使用“全部允许”回避检查。这个检查证明未变化部件的字节一致，不能代替目标正文内部范围核对和页面复核。

## 真正的修订

用户要求修订时，为新增和删除的 run 分别使用 `<w:ins>`、`<w:del>`，提供不冲突的 `w:id`、用户指定的 `w:author` 与真实时间 `w:date`。未给作者时使用“审阅者”，不冒充用户姓名。

删除内文本必须为 `<w:delText>`，不能留 `<w:t>`。删除段落需要删段落内的 run，同时把段落标记删除写到 `<w:pPr><w:rPr><w:del …/></w:rPr></w:pPr>`；该 `<w:del/>` 必须在 rPr 的其他子元素之前。保留原有修订，不擅自接受或换作者。

```bash
python3 scripts/run.py validate 新稿.docx --original 原件.docx --author 审阅者
```

此验证会把新增修订还原后与原文比对，以发现漏标修订的文本变化；只覆盖主文档正文，不证明页眉、页脚、脚注和批注中的每项改动都已追踪，因此这些部件需另查。只有结构通过不能宣称 Word 已经实际显示修订。

## 批注与回复

批注不仅是一段文字，还需要关联部件和正文锚点。使用成熟 helper 建立批注部件：

```bash
python3 scripts/run.py comment 工作目录 "这处交付时间请确认" --author 审阅者
python3 scripts/run.py comment 工作目录 "已补充依据" --author 审阅者 --parent 0
```

也支持 DOCX 直接输入及 `-o 新文件.docx`。先确认 parent 是真实存在的父批注编号；文本默认 XML 转义，普通用户文字不要使用 `--raw`。

工具会自动分配批注 ID，并建立 comments、extended、ids、extensible、关系与内容类型部件。**随后必须按它输出的片段将 `commentRangeStart`、`commentRangeEnd` 和 `commentReference` 放在目标段落的准确范围**；标记是 `w:p` 的直接子元素，不能塞进 `w:r`。回复锚点嵌在父批注范围中，并保留双方 reference。没有锚点的批注不能宣称用户可见。

重新读取所有批注文字、作者、回复关系和正文范围；在 Word 或可验证的原生视图检查可见性。PDF 渲染经常不显示批注，不能仅凭 PDF 证明批注正确。

## 接受全部修订

仅在用户要求清洁版时运行：

```bash
python3 scripts/run.py accept-all 修订稿.docx 清洁稿.docx
```

该流程使用隔离的 LibreOffice 配置和工作副本，拒绝覆盖旧文件。超时或仍含修订标记时失败，不宣称完成。接受后的正文、段落和编号仍须检查：被删除段落后接空白段落时，转换器可能留下空段/空编号项；不能把这个显示差异当作原修订文档必然有错，也不能不检查就交付清洁稿。

## 不依赖转换器的普通文字清洁副本

如果整份文件只有主文档段落内普通文字run的插入和删除，执行：

```bash
python3 scripts/run.py accept-text --input 修订稿.docx --output 清洁稿.docx
```

它直接保留原 OOXML：去掉普通插入的包装、删除标记为删除的文字；未涉及的 XML 字节、批注、回复、样式、表格、图片、页眉页脚及其它包部件保持原样，不重建文档。接受范围包含文件中所有符合条件的文字修订，含既有审阅者的修订，因此仅在用户要求接受全部修订时使用，不擅自只按作者猜测范围。

**明确拒绝**：段落标记删除/插入、移动、格式或表格结构修订、嵌套修订、修订内图片/域/换行/批注边界、其它部件中的修订、签名/宏文档，以及不支持的编码或扩展属性。一项超出范围即不交付清洁文件，不先处理部分后把剩余修订藏起来。用户不要求接受时保留修订原状。

成功后仍需完整结构验证、正文与段落/编号核对及页面检查。此路径不更新目录页码，不证明任意复杂文档均可自动接受修订。完整文档引擎路径始终保留；引擎缺失或失败时明确说明。
