# 文件验收

## 结构与原件

1. 确认输出是有效 ZIP/OOXML 包，并实际读出 `word/document.xml`，不是改后缀的文本。记录原件前后哈希一致。
2. 对新稿运行 `python3 scripts/run.py validate 新稿.docx`。对编辑稿追加 `--original 原件.docx`；修订任务再加 `--author 审阅者`。保留实际退出码和诊断，不把命令被调用当作通过。
3. `--auto-repair` 会修改输入，**只对工作副本使用**。它可修常见ID范围和空白保留问题，不会自动修复所有文档。修后重新校验和渲染。
4. 局部修改检查未指定部件字节相同、未目标文字及既有样式/编号/图像/页眉页脚内容保留。新增修订和批注需分别核对结构、作者、文本及锚点。

## 逐页视觉检查

在新验收目录执行：

```bash
python3 scripts/run.py convert --headless --convert-to pdf --outdir 验收目录 新稿.docx
pdftoppm -png -r 120 验收目录/新稿.pdf 验收目录/page
```

检查真实 PDF 非空，页图数量与 PDF 页数一致，打开全部页图。页码可能补零，按实际文件列表读取，不能猜文件名。检查中文缺字、标题层级、列表编号、表格边界与跨页、页眉页脚、图片裁切和大段空白。修改任何影响内容或排版的项目后重新渲染最新版本。

无法渲染或无法查看图像时，准确标记“结构已检查，页面版式未验收”，不得写“版式已确认”或“与原版完全一致”。存在原生编辑器时可以用于补充验收，但先验证其实际能力，不能只因工具名称含Word就认定等价。

## 交付判定

只有真实文件存在、结构检查与对应范围核对完成，才能声称文件已经生成；需要正式排版成稿时还要通过最新逐页检查。批注需结构与可见性核验，修订需覆盖检查与实际阅读确认。使用有限输入的通过只代表本轮任务，不能宣称任意复杂Word格式均无损。

依赖、权限或转换器不足时保留完成的文件与日志，说明具体缺口。不能安装未知软件、调用外部服务替代本地流程、降低原任务范围后当作全部完成。不得自动发送、签署或上传用户材料。

## 目录与清洁版的额外检查

目录域存在不代表目录可见或页码已更新。必须读出真实目录条目并在最终页面中逐条核对标题和页码；仅转换 DOCX 或 PDF 不能自动算作更新成功。没有可用的域更新引擎时明确记录“目录域已创建，条目和页码尚未更新”，不手写猜测页码。

`accept-text` 的完成消息只证明受支持的普通文字修订和部件保护检查通过。检查清洁版已没有残余修订、原件未变、批注仍在、目标正文正确，再打开每页确认。`accept-all` 的工具退出、超时、生成了副本，都不能单独证明修订已经接受。
