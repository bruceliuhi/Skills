# 新建真实Word文档

## 执行方法

在任务的新工作目录编写本次文档的 JavaScript 脚本，使用 `require('<本技能实际目录>/vendor/docx.cjs')` 的完整 API 与 `Packer.toBuffer` 生成 DOCX；写出时使用独占创建，拒绝覆盖已有文件。生成库已随包提供，不执行 `npm install`，不引用开发者电脑或 Codex 的依赖路径。加载失败先检查本技能实际安装目录和 Node 是否可用，不切换到伪DOCX。

先把资料整理成标题、正文、列表、表格、图片和必要的页眉页脚；同一文档建立一致的样式。正文事实沿用用户材料。用户提供图片时保留原文件，指定图片格式和尺寸比例；无图片材料不能编造“已嵌入原图”。

## 必须保留的格式能力与常见陷阱

- 默认 A4；Letter 为 12240×15840 DXA，1440 DXA 等于一英寸。横向页面提供原竖向宽高并设置 `PageOrientation.LANDSCAPE`，库会交换尺寸。
- 使用内置 `HeadingLevel` 标题和正文样式；自定义标题设 `outlineLevel`。目录由真实标题结构生成，不能只写一份看似目录的手工页码表。打开文档时需要更新域的，明确说明并验收缓存显示。
- 表格同时设置表格 `columnWidths` 与每个单元格的 DXA 宽度；列宽之和等于表格宽度。百分比宽度在其他编辑器中可能漂移。单元格背景使用 `ShadingType.CLEAR`，不使用会变黑的 SOLID。
- 编号和项目符号使用真实 `numbering` 配置与 `LevelFormat`，不能用手打“•”或空格排列冒充列表。核对编号续排与重启。
- 使用独立 `Paragraph` 表达段落，不能用字符串中的换行代替段落。分页使用 `Paragraph` 内的 `PageBreak`，根据内容设置段前分页、与下段同页和表头重复。
- `ImageRun` 必须提供 `type`（如 png、jpg），保留宽高比，并检查内嵌关系与图片实际存在。使用 `altText` 时填写 `name`、`title` 和 `description`；缺少 `name` 可能生成缺必填属性的图像结构，必须通过XSD检查。
- 页眉页脚用真实 Header/Footer；页码用页码域。是否需要这些元素以用户场景为准，不为了展示功能强行增加。
- 同行右对齐、点引导线使用 `PositionalTab` 及对应 alignment/leader，不堆空格和点号。分隔线确有必要时用段落边框，不插一行表格。
- 中文字体要确认运行环境和目标编辑器可用；不要把“指定了字体名”当作已嵌入或已渲染。

## 模板格式

DOTX 是 Word 模板类型，不是只改后缀。转换时核对 `[Content_Types].xml` 的主文档类型为模板类型，并通过结构验证；保留样式、编号、页眉页脚、主题和图像。宏文件 DOCM/DOTM 不在默认处理范围，不执行嵌入宏。

最终按 @references/quality.md 完成重新读取、结构校验和逐页渲染。若用户只是改一份已有文档，转到 @references/edit-review.md，不能沿用新建路径重做全文。
