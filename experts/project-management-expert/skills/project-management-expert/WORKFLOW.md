# 项目管理工作流程与方法资料

本包四类可执行能力以 `SKILL.md` 和 `references/input-and-output.md` 为准。本文件保留项目治理、组合评审、优先级和交接的工作方法。方法资料中出现的统计、投资、工具集成或实时跟踪，不表示本包已有相应算法或连接器；未经真实执行与验证，不写入“已完成能力”。

## 1. 从材料到可执行计划

先确定要解决的是排期、人手、健康还是风险；一次可以组合多种分析，但每种使用自己的输入结构，不把一份“组合大 JSON”直接喂给所有脚本。

- 计划：读取里程碑、前置关系、负责人、已确认工期、可用窗口和假期。运行 schedule，查关键链、浮时、同人冲突和期限，再对指定工期变化重算。
- 人手：先确认每周工时、当前利用率、开销比例、费率、技能和项目周分配的口径。运行 capacity，比较有效容量、需求、缺口及独立情景。
- 健康：先确认全部指标可用且一致。运行 health，解释五维得分和阶段背景，不能将低范围完成度直接等同于管理失误。
- 风险：先确认分析日期、风险等级和措施记录。运行 risks，查类别、矩阵、逾期和措施覆盖；评分不是统计概率。

### 可直接运行的练习输入

```bash
python3 scripts/project_manager.py schedule --input assets/schedule-example.json --out ./schedule-delivery
python3 scripts/project_manager.py capacity --input assets/capacity-example.json --out ./capacity-delivery
python3 scripts/project_manager.py health --input assets/health-example.json --out ./health-delivery
python3 scripts/project_manager.py risks --input assets/risks-example.json --out ./risks-delivery
```

这些样例是结构与操作练习；不代表真实客户、项目成效或平台试跑。输出目录须未存在。使用真实资料时由 WorkBuddy 映射为对应输入，并且不得把缺少字段默认成零。

## 2. 周度项目与组合评审

1. 记录本次材料日期和范围，核对与上次版本的变化；缺失项列为“待提供”。
2. 有完整指标时运行健康分析：工期25%、预算25%、范围20%、质量20%、风险10%；综合分 ≥80 绿、≥60 黄、其余红。这是固定启发式模型，不附加未实现的“任何单维低分自动变红”条件。
3. 运行风险分析：按概率等级×影响等级×类别系数排序，区别活跃和非活跃状态；本次记录里没有缓解措施不等于实际无人处理。
4. 运行容量分析：有效周容量＝工时×（1−开销），对比项目周需求；技能匹配仅提供备选资源，不自动分配。
5. 如排期是核心问题，运行依赖计划及用户指定的延期情景；保留基线和新结果，不通过擅改期限来“解决”阻断。
6. 使用 `assets/executive_report_template.md` 整理中文管理层报告：本期结论、变化、需要决策的事项、依据和下一步。没有历史数据就删去趋势占位，不生成同比或“已改善”结论。

所有升级、变更、分配和通知先作为建议或草稿。生成报告不等于发送消息、更新项目系统或获得批准。

## 3. 项目章程与责任分配

保留并按需使用三个完整模板：

- `assets/project_charter_template.md`：背景、目标、范围、成功标准、里程碑、预算、资源、风险、治理与批准。
- `assets/raci_matrix_template.md`：人员职责、分阶段责任、沟通、冲突处理及升级路径。每项责任按用户实际权限填写，不自造负责人；检查是否需要唯一最终负责者。
- `assets/executive_report_template.md`：组合健康、风险、容量、预算及管理动作。模板里数值和示例图均是占位；无证据则删去或标待补。

生成时保留结构，删除不适用部分并说明理由。输出完整可复制 Markdown；具备真实写入能力时写成 `.md`。本包不声称自动生成原生 DOCX、PPTX 或连接在线项目管理软件。

## 4. 月度优先级评审（方法，不是自动求解）

`references/portfolio-prioritization-models.md` 保留 WSJF、RICE、ICE、MoSCoW 等方法细节。

- WSJF 适合已有可比延迟成本和工作量的数据；分母必须为正。
- RICE 需要同一期间的触达、影响、置信度和投入口径；百分比先转为0–1，投入必须为正。
- ICE 的加法均分与乘积是不同变体，使用前确认，不能混用结果。
- MoSCoW 是范围取舍讨论，不把 Must 列表当成已确认资源承诺。

只用用户给出的评分和指标，列公式与假设；没有可比数据时给评分表和缺项，不编排名。当前命令入口没有这些模型的专用自动优化器。不能把简单加权或排序宣传为跨项目最优资源配置。

## 5. 风险方法资料的使用条件

`references/risk-management-framework.md` 保留分类、风险偏好、三点估算、EMV、模拟和治理方法说明；`references/portfolio-kpis.md` 保留指标口径示意。

当前脚本计算等级矩阵、加权分、类别汇总、措施记录覆盖和按指定日期的逾期状态。以下不属于已实现功能：蒙特卡洛模拟、风险间相关性、NPV、统计置信区间、风险速度、实时历史趋势。

EMV 仅在另行取得0–1真实概率及同币种金额影响、明确模型并计算校验后才有意义；**不能用1–5概率等级直接乘金额**。三点估算不等于已经跑蒙特卡洛。风险累计分不能直接代替金额损失、NPV折现率或成功概率。

参考文档中的阈值、风险偏好和预备金百分比仅为方法示例，不是客户制度或行业要求。需要实际生效规则时以用户提供的批准口径为准。

## 6. 季度复盘与交接

季度复盘先核对实际交付、投入与已确认结果，再讨论保留、调整或停止的项目。收益、ROI、投资回报和市场价值没有来源时标未知，不能由健康分推导。

给项目负责人/产品负责人/交付团队的交接包含：目标与验收标准、已确认范围、任务与依赖、人员可用性、预算口径、风险、未决事项和下次核对日期。每项给出责任人或待指派，不自动承诺时间与资源。

可以整理 Jira、飞书或其他系统人工导出的资料；本包没有这些系统的读取、写入、实时同步或消息接口，也不要求用户另开账号。对外发送和变更应在独立获授权流程中处理。
