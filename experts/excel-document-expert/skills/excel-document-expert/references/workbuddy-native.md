# WorkBuddy 原生 Excel 路径

用户只需提供文件和目标。本路径利用当前 WorkBuddy 会话已有的表格编辑器与计算能力，不要求额外第三方账号、API 密钥或手工安装依赖。先发现工具与平台内置技能，不能假定所有客户端版本或付费云端都已提供相同能力。

## 从材料到真实文件

1. **确定文件与保护原件。** 读取用户上传/明确指定路径。先用新名字复制为工作副本，记录原件摘要；不要直接在原件上调用写入工具。目标成果路径必须尚不存在。
2. **发现并读取。** 检查当前实际注册的表格工具和它们的参数说明。已验证的工具组合包括 `resolve_local_excel`、`read_table`、`get_cell_ranges`、`set_cell_range`、`calculate_formulas`，但只能调用当前会话确实提供的工具。由返回结果取得工作表 ID，不臆造 ID。先读表名、目标范围、公式、类型及本次需要保留的对象。
3. **精确编辑。** 用已支持的单元格/区域编辑功能，只改用户指定输入或本次明确生成的范围。例如改某单价时仅写该数值格，保留金额格和汇总格的公式。工具的覆盖参数仅用于工作副本里获准修改的范围，不代表可以覆盖原件。
4. **真实计算。** 使用当前原生计算能力，并带正确工作表/公式锚点。重新读取受影响公式、依赖链和实际缓存；计算接口返回一个正确答案，不等于工作簿中的公式和缓存已经更新。检查日期格式、错误类型、零分母、空字符串和未计算缓存，未知公式结构不要只验一个格就通过。
5. **必须保存。** 表格工具可能只改编辑器池，磁盘文件仍未变化。优先用当前已注册的保存/导出功能。若该功能由平台内置 `workbuddy-local-office-edit` 技能提供，先读取当前平台给出的技能入口及脚本帮助，再使用其 `editor_sdk`/`edsdk.py` 的 `save_file` 能力，将当前编辑器文件 ID 保存到新的成果路径。以本次实际说明中的参数为准；不硬编码某台机器的安装路径，不自行下载该工具。没有可用保存能力就明确“编辑器内已修改，尚未交付文件”，不能给出原副本冒充成果。
6. **复读磁盘成果。** 确认新文件存在、可重新打开；分别核对公式与缓存。比较原件摘要、未涉及区域、编号类型、工作表/隐藏状态、命名区域、验证、冻结、筛选、样式与原生图表引用。图表要仍为可编辑对象，而非截图。需要布局时检查真实预览。
7. **直接交付。** 给用户真实成果文件、关键变更和已核验结果。内部工具名、文件 ID、调试记录不写成冗长产品使用步骤；只有遇到能力缺口时说明影响与可行下一步。

## 单独判断的边界

- 普通多表工作簿已验证“读取→局部修改→引擎重算→原生另存→复读”路径；这一代表性验证不等于所有 Excel 功能都已兼容。
- 动态数组/共享公式/数据表公式、透视表刷新、宏、外部链接、切片器与数据模型，必须用本次文件验证；缺少能力或结果无法解释时停止写回。
- 样式保留按实际语义比较；引擎可能规范化颜色编码或公式中的工作表引号，不保证 ZIP 字节相同。字体替换、值或公式丢失、原生图表变静态图不能视为无影响变化。
- 本地脚本的依赖探测没有发现库，不代表当前原生表格工具不可用；原生会话通过也不证明付费云端通过。每次以实际可调用、可计算、可保存、可复读为准。
