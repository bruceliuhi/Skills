# 保存作品、继续写作与导出

命令中的项目路径、输入文件和技能路径必须替换为本次真实路径。脚本从技能包目录调用；当前环境先确认可用的 Python 3，不安装第三方依赖。先建立项目父目录和导出目录；项目本身必须是尚不存在的新目录。参数名称是机器接口，面向作者用中文解释结果。

## 新建与规划

```sh
python3 scripts/novel_project.py init --project "作品/夜航来信" --title "夜航来信" --genre "悬疑" --chapters 12
python3 scripts/novel_project.py plan --project "作品/夜航来信" --file "本轮写作计划.json"
```

计划文件结构参考 [写作计划模板](../templates/写作计划.json)。其中章节标题与目标需要针对真实创意填写；模板只是数据格式，不是已完成故事。`characters`、`world`、`style`、`foreshadowing`可存中文对象和文字，分别保存人物档案、世界规则、作者偏好与伏笔。`plan`每次接收完整的新章节计划，不是只提交一个增量章节；拒绝空计划，允许缩短尚未写作的部分，但不会删除已经写入的正文。旧计划保存在项目中。

正文先保存成单章 UTF-8 文本，只放正文段落，不重复写章名。标题通过`--title`单独保存，导出时生成章标题。不要把大纲、创作分析、检查结论混入正文。把分析放在独立说明或review中。

```sh
python3 scripts/novel_project.py add --project "作品/夜航来信" --number 1 --title "关门后的站台" --file "本轮首章.md" --summary "概括本章已经发生的事件、人物处境改变和结尾未解决的问题。"
python3 scripts/novel_project.py status --project "作品/夜航来信"
python3 scripts/novel_project.py context --project "作品/夜航来信" --next 2
```

`context --next N`提供N章之前的最近章节摘要；若N章已存在，同时给出该章修订位置，并提示后续章节范围。当前稿以manifest索引及`status`/`context`返回的真实`text_path`为准，不猜`latest.json`，不按文件修改时间选稿。摘要不等于已经读过正文，写续章前按返回路径回读。用户旧稿逐章导入；无法确定分章时按明确标题或用户确认的切分处理，不平均切块冒充章节。跨会话恢复须保留且能访问整个作品目录，只有导出的Word或TXT不包含全部修订与事实档案。

`status`、`context`、`audit`、`export`使用一次读取的完整manifest快照及其不可变修订，可以并行；若同时发生写入，结果可能是提交前或提交后的完整版本，以返回的SHA为准。`plan`和`add`仍互斥，写入冲突先等当前写入完成再重试；不删锁、不改名历史目录。

## 查看长篇来源目录

```sh
python3 scripts/novel_project.py context --project "作品/夜航来信" --next 6 --catalog
python3 scripts/novel_project.py context --project "作品/夜航来信" --next 6 --catalog --entity "林岚"
```

`--catalog`只自动收录各章通过`--facts`保存的事实记录，以及计划中的`plan.foreshadowing`。世界档案或独立中文记录不会自动入目录，须手动回读或按实际证据登记。目录可分页，`--entity`按事实/伏笔的entity字段精确筛选，不是语义搜索。根据返回正文路径读取相关早章；目录和摘要不能替代原文。伏笔若只有计划而没有实际原句，保留“来源未核实”，不能称已埋设或已回收。

建议有证据的伏笔写为`{"id":"线索一","summary":"具体线索","status":"未回收","evidence":{"chapter":1,"quote":"正文中确实存在的完整原句"}}`。不要把示例原句当作真实写作成果。

## 修订与记录事实

修改已有章前读取当前状态中的正文SHA，并将它作为`--base-sha`传入；发生版本不一致时重新读取当前稿件，不强行覆盖。新的正文与历史版本均在项目中保存。

```sh
python3 scripts/novel_project.py add --project "作品/夜航来信" --number 1 --title "关门后的站台" --file "首章修订稿.md" --summary "本次修订后的事件摘要" --base-sha "当前正文的实际SHA值" --review "首章复核.json" --facts "首章事实.json"
```

`--review`是可选校稿记录，建议使用中文键：检查范围、问题、原文位置、建议、待确认事项。工具保存记录，不会把模型自评自动判定为通过。

`--facts`是可选数组，结构如下。引用必须在相应正文中实际存在；事实解释仍需人工或模型判断，不能仅因引用存在就宣称理解正确。

```json
[
  {
    "entity": "林岚",
    "attribute": "本章持有物",
    "value": "车票",
    "evidence": {"chapter": 1, "quote": "林岚把车票收进外套内袋。"}
  }
]
```

新事实不得直接抹去旧记录。同一属性改变时，检查变化是否有剧情原因；人物认知、伪装、误导与客观事件分开写。希望由目录定位的伏笔放入`plan.foreshadowing`，包含埋设章、原句和状态；额外中文记录可保留，但恢复时须单独回读。不得把计划中的线索说成正文已埋设。

## 检查与导出

```sh
python3 scripts/novel_project.py audit --project "作品/夜航来信" --min-cjk 3000 --max-cjk 5000
python3 scripts/novel_project.py export --project "作品/夜航来信" --output "交付/夜航来信-当前稿.md" --format md
python3 scripts/novel_project.py export --project "作品/夜航来信" --output "交付/夜航来信-当前稿.txt" --format txt
python3 scripts/novel_project.py export --project "作品/夜航来信" --output "交付/夜航来信-当前稿.docx" --format docx
```

`--min-cjk`和`--max-cjk`检查正文汉字数；标点、空白、数字和拉丁字母不计入。具体包含的Unicode范围由脚本报告。旧参数`--min-chars`仍检查非空白字符数，包含标点、字母和数字，不能代替汉字目标；这些工具口径也不能冒充特定阅读平台的字数标准。缺章时可以交付“第1—3章当前稿”，但不能称完整长篇。`--output`绝对路径表示明确的交付位置，相对路径以作品项目为根；父目录须先建立。输出文件存在时使用新版本文件名；Word导出用于可编辑稿件，复杂排版另按作者要求完成。

脚本无模型调用，不会自动写正文、自动判断人物动机或预测签约。没有Python时可以交付纯正文，但不能声称作品已存档或已产生文件。
